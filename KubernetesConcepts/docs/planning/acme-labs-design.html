What we are building, and what we are deliberately not

Minimal footprint, maximum exposure to the hidden networking and identity mechanics

Build

  • 1 private zonal GKE cluster (Dataplane V2)
  • 3 domains: orders (Go), payments (Python), inventory (Node)
  • Per pod: app + Envoy + OTel collector + Fluent Bit
  • 1 central log bucket, one Log Router sink
  • Custom VPC with real IPAM, 4 egress doors
  • GitLab CI → GCP via no-key federation
  • Flux + Helm for everything in-cluster

Design principles

  • Terraform owns GCP; Flux owns Kubernetes
  • Shared code lives in Tier 1 modules (versioned)
  • Secure by default: deny first, then open doors
  • Identities are deterministic names, not lookups
  • Build with training wheels, then remove them (P8)
  • Every phase ends with a predict-then-verify gate

Not now (stretch menu)

  • Cloud SQL via PSA (100.64/20)
  • Hybrid HA VPN + NCC-style site
  • Per-domain node pools / Shared VPC
  • Consul contract bus + self-hosted runner
  • Cloud Storage / Firebase / Pub/Sub via Tier-1 modules
Cost: a few $/day while up, ≈ $0 destroyed. Budget alarm first.

Why one cluster is right for the lab

  • Free-tier management-fee credit covers one zonal cluster
  • You still touch every network concept (ranges, NAT, routes, DNS, LB)
  • Three clusters would triple cost and teach little extra

When you would need more

  • Hard regulatory network separation → separate clusters / Shared VPC with 3 subnets (S3, S6)
  • Different upgrade cadences or blast radius

IPAM: four kinds of address space, four different reasons

Decide the table before writing Terraform — pod/service ranges are hard to change later
1 · Primary / routable

Nodes 10.10.0.0/24 · ops 10.10.1.0/28 · master 10.10.250.0/28

  • The only space you'd ever advertise to on-prem/VPN
  • Must never overlap anything you may later connect
  • Master range: mandatory /28 for the private control plane
2 · Pods & Services

gke-pods 10.20.0.0/20 · gke-svcs 10.30.0.0/24

  • Secondary ranges on gke-main (VPC-native alias IPs)
  • max_pods_per_node=64 → /25 per node → up to 32 nodes
  • Hybrid: pod IPs unknown to on-prem → masquerade (S2)
3 · Private Services Access

100.64.0.0/20 (stretch S1)

  • Peered range for Cloud SQL via servicenetworking
  • RFC 6598 space: doesn't burn scarce 10.x
  • Peering is non-transitive
4 · Proxy-only

proxy-only-subnet 10.10.254.0/23

  • purpose = REGIONAL_MANAGED_PROXY
  • Google's Envoy fleet for internal L7 LBs / gke-l7-rilb
  • Your VMs/pods never get an IP from it — but firewalls must allow it to your nodes

Why the default internet route is deleted — and the four outbound doors

Lab: start with a "training wheels" default route, then remove it (P8) and repair every break

Unknown IP ⇒ packet dropped (no route)

Door 1 · Google APIs PGA + private VIP
Subnet private_ip_google_access=true + route 199.36.153.8/30 + private DNS (*.googleapis.com / gcr.io / pkg.dev → private.googleapis.com). Logging, GCS, Artifact Registry.
Door 2 · /32 allow-list Explicit routes, priority 900
One inet-<name> route per approved external IP (map variable vip_allowlist).
Door 3 · Cloud NAT + tag Route prio 999 for tag allowed-open-nat
Two static NAT IPs so partners can allow-list you. NAT only translates traffic whose next hop is the internet gateway. Tags are node-level — pods inherit.
Door 4 · Hybrid (stretch S2) HA VPN + Cloud Router → onprem-sim VPC
BGP routes, DNS peering, ip-masq-agent for pod traffic. Stands in for NCC/on-prem.

Sidecars → one central Cloud Logging

Three delivery patterns for the same goal; one Log Router sink collects the three domains

Domains talk to each other — only the way you allow

Two independent guards; each fails with a different signature (timeout vs 403)

Guard 1 · NetworkPolicy (L3/4)

default-deny both directions + explicit allows. Egress must also allow DNS, istiod (15012), GKE metadata server (169.254.169.252:988) — or Workload Identity silently breaks.

Guard 2 · Istio AuthorizationPolicy (L7)

payments accepts only cluster.local/ns/dom-orders/sa/orders over STRICT mTLS. Failure signature: HTTP 403 (RBAC).

Why both

Network path ≠ caller identity. Remove guard 1 and test: you now see guard 2 alone — and learn to read each layer's error.

Growing the platform later without copy-paste

Add Cloud Storage, Firebase, Pub/Sub, Cloud SQL as Tier-1 modules consumed at Tier 3

1 · Write once (Tier 1)

  • terraform-modules/modules/gcs-bucket
  • Secure defaults baked in (uniform access, public-access prevention)
  • Release a tag: v0.2.0

2 · Consume (Tier 3)

  • module "uploads" { source = "...//modules/gcs-bucket?ref=v0.2.0" }
  • Grant the domain GSA writer access
  • State is per project — blast radius stays small

3 · Wire to the app

  • Deterministic bucket name into HelmRelease values
  • Workload Identity already gives the pod access
  • Update NetworkPolicy/doors only if a new destination appears
